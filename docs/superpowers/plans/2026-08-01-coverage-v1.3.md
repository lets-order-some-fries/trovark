### Task V1 — Monorepo sampling overhaul (`src/collectors/github.ts`) — THE ENABLER

Per coverage-spec §3.3 + §4. Root cause: `FILE_CAP=12` filled by manifests before tool source is reached; shortest-path tie-break picks `index.ts` over `tools-registry.ts`; entrypoints >100KB skipped entirely.

Changes (all in `github.ts`):
1. `SOURCE_EXT`/`SRC_EXT` → `/\.(ts|js|mjs|py|go|rs|java|cs|kt)$/` (adds the languages; extractors wired in later tasks — fetching them now is harmless).
2. Tighten `isManifest`: root-only `mcp.json`/`server.json`; exclude paths under `.cursor/`, `.vscode/`, `**/data/**` (spec §3.3a).
3. Dynamic budget (spec §3.3b): `FILE_CAP` = 24 when the root `package.json` has `workspaces` OR >3 manifests in tree, else 12. `MANIFEST_QUOTA = min(manifests, 3)`. `SOURCE_FLOOR = ceil(FILE_CAP*0.66)` — if selected source < floor, evict lowest-priority manifests. Lockfiles stay LAST (from v1.2).
4. Replace shortest-path tie-break with `toolSignalScore(path, pkgName)` (spec §3.3c): +5 `tools/` dir, +5 `.tools.ts`, +6 `tools-registry|toolDefinitions`, +4 `/mcp/` or pkg name ends `-mcp`, +2 `server|index|main` entrypoint, −10 non-server path. Resolve `pkgName` from nearest `package.json`. Sort desc; path.length only as final tiebreak.
5. Raise `SIZE_CAP` 100_000 → 300_000; for an oversized ENTRYPOINT (index/server/main), fetch-and-truncate to 300KB rather than skip (firecrawl index.ts is 104KB).
6. Add `samples` to the non-server-dir exclusion set.

- [ ] RED tests (`tests/github.test.ts`): a tree with 10 nested `package.json` + a `packages/mcp/src/index.ts` → the source file IS fetched (not starved) under the raised cap + source floor; a `src/tools/registry.ts` outranks a shorter `src/index.ts` via toolSignalScore; a 150KB `src/index.ts` is fetched (truncated) not skipped; a `.cursor/mcp.json` is NOT treated as a manifest; a `.go` file is now fetched.
- [ ] Implement; keep all prior github tests green (the existing lockfile-last, .env, dedup behavior preserved); `npm test` + build green.
- [ ] Commit `fix(collectors): monorepo sampling — dynamic budget, tool-signal ranking, larger entrypoints`.

### Task V2 — Library/SDK/proxy classifier (biggest correct-outcome converter)

Per coverage-spec §3.1 + §3.6. When `tools.length === 0`, decide whether the repo is a library/SDK/proxy/stub (→ report "not a server", a correct terminal outcome) vs genuinely un-parseable (→ keep insufficientData). ~40-55 of 189 are libraries.

Files: new `src/derive/classify.ts` (`classifyLibrary(ctx): { notServer: true, reason, note } | null`), `src/types.ts` (add `notServer?: boolean` + `notServerReason?` to Scorecard), `src/derive/schema.ts` (call it in the zero-tools path and surface the result), `src/scoring/score.ts` (a `notServer` scorecard is NOT `insufficientData` — it's a distinct terminal state; report renders "Library / not an MCP server"), `src/report/terminal.ts` + `index/site.ts` (render the distinct outcome), tests.

`classifyLibrary` signals in priority order (spec §3.1): (1) `-sdk` repo name / "official … SDK" description / topics include sdk|library|framework → `sdk`; (2) tool idioms exist but ONLY under example/doc/sample paths → `sdk`; (3) no MCP SDK import anywhere + no mcp.json/server.json → `not-server`; (4) remote-proxy (StreamableHTTPClientTransport + runtime tool registration) → `proxy`; (5) distribution-stub (server.json points to a different npm pkg, zero local registrations, "where is the source" redirect) → `stub`. Guard: only ever runs at `tools.length===0`.

- [ ] RED tests (`tests/classify.test.ts` + `tests/schema.test.ts`): a repo named `foo-sdk` with description "The official Foo SDK" and zero tools → notServer reason 'sdk'; a repo whose only `.tool()` hits are under `examples/` → notServer 'sdk'; a repo with no MCP import and no manifest → notServer 'not-server'; a normal server that DID extract tools is NEVER classified notServer (guard). Score/CLI: a notServer result is not insufficientData and the report shows "not an MCP server".
- [ ] Implement; keep the 211 graded + the insufficientData behavior for genuine misses intact; green.

### Task V3 — Go tool extractor (biggest grade converter, ~25-35)

Per coverage-spec §3.2. New `src/derive/lang/go.ts` `fromGoSource(file): ToolInfo[]`, wired into `extractSchema` for `.go` files. Four idioms (all from real repos):
1. Official go-sdk composite literal: locate `mcp.Tool{`, captureBalanced, name `/Name:\s*"([\w.-]+)"/`, description from `/Description:\s*t\(\s*"[^"]*"\s*,\s*"([^"]*)"/` (translation helper 2nd arg) or fallback `/Description:\s*"([^"]*)"/`.
2. mark3labs call form: `/\bNewTool\(\s*["'`+"`"+`]([\w.-]+)/g`, description from adjacent `WithDescription(` via captureBalanced.
3. mark3labs `MustTool`/positional: `/\b(?:MustTool|NewTool)\(\s*["'`+"`"+`]([\w.-]+)["'`+"`"+`]\s*,\s*["'`+"`"+`]([^"'`+"`"+`]*)["'`+"`"+`]/g` (name+desc).
4. genai-toolbox self-register: signal `/\btools\.Register\(/`; name `/const\s+resourceType\s+string\s*=\s*"([\w.-]+)"/`; desc `/\.Description\s*=\s*"([^"]*)"/`.
(cobra-mcp / yutu is optional — include only if cheap: if content imports `cobra-mcp`, enumerate `Use:"..."` under cmd/. Otherwise skip, it's 1 server.)
Dedup names. Feed extracted tools through the SAME classify()/token-set risk path as JS/Py (so `call_tool_destructive` tiers correctly).

- [ ] RED tests (`tests/go.test.ts`): each of the 4 idioms extracts the right tool name(s)+description from a real-shaped snippet; the github-mcp-server `mcp.Tool{Name:"get_file_contents", Description: t("KEY","Get the contents...")}` yields `get_file_contents`; the grafana `MustTool("search_dashboards","Search for...")` yields name+desc; malformed Go → [].
